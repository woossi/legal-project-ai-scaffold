# 구성 (스킬 폴더 기준 상대 경로)

- `contract/inputs.json` — 입력 산출물 7종의 취급 규칙. 파일 구조의 정본은 legal-term 스킬의
  `contract/outputs.json`
- `contract/graph.json` — 관계 6종 값 도메인, 간선 추가 요건, 임포트 멱등성·불변식
- `case/실질충돌설계.md` — 실질충돌 용어의 통합·분리 판단 절차
- 온톨로지 구조·IRI 규약·검증 게이트는 `kb-ontology` 스킬에 있다. 이 스킬은 기획만 담당한다
- 스크립트는 두지 않는다. 기획 단계 스킬이며 규칙과 계약만 둔다

# 실행

## 절대 규칙

1. 원문 문자열과 미검증 파생값을 스키마에서 분리한다. 파생값에는 생성 근거를 남긴다.
   같은 필드에 섞으면 이후 원문 복원이 불가능하다
2. `source_quality: "OCR"` 항목은 별도로 취급한다. 수치·단위·기호를 신뢰하지 않는다.
   원문자(①~⑳)·㎡·% 가 소실되거나 오인식된다
3. `classification_confidence: low` 항목은 확정 분류가 아니다. 소유자 확정 전까지 임시
   상태로 표시하고 확정분과 섞어 집계하지 않는다
4. 설계 승인 범위를 넘지 않는다. 스키마 변경과 클래스 추가는 선제안 후 승인받는다
5. 추측 관계를 넣지 않는다. 그래프 신뢰도는 가장 약한 간선이 결정한다

## 절차

- 입력 파일별 취급은 `contract/inputs.json` 을 따른다
- 관계를 추가할 때는 `contract/graph.json` 의 간선 요건을 충족한다. 요건은 관계의 `origin`
  에 따라 갈린다. `origin=지구` 는 정의문 원문의 진술과 출처 지구번호를 요구하고,
  `origin=법령` 은 조문 출처(URL)와 시행일을 요구한다. 법령은 개정되므로 시점 없는 조문
  인용은 근거가 되지 않는다
- `origin=법령` 간선은 검증상태가 `정본대조` 인 법령·조문에서만 만든다. 미대조 표기는
  실측 표기의 정규화값이지 정식 명칭이 아니다
- 실질충돌 용어의 통합 여부는 `case/실질충돌설계.md` 의 절차로 판단하고, 결정 근거를
  메모리에 남긴다
- 임포트 후에는 불변식 pytest 와 건수 대조표로 검증한다. 검증 항목은 `contract/graph.json`
  에 있다
