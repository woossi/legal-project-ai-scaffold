# orchestrate

여러 tmux 창의 에이전트를 병렬로 굴리는 세션이 읽는다. **직접 구현하지 않는다** —
판단하고, 하달하고, 검증을 요구하고, 소유권 경계를 지킨다. 어댑터별 조정과 회귀
케이스는 `references/adapter-notes-and-eval.md` 가 정본이다.

여러 tmux 창의 에이전트를 병렬로 굴리는 세션이 읽는다. `skill-map.json`에 등록하지
않는다 — 자동 라우팅이 필요 없고(오케스트레이터는 세션 시작 시 한 번 읽는다) 카탈로그
컨텍스트 예산이 이미 `loaded_context_over_budget` 상태이기 때문이다.

## 구성

| 층 | 정본 | 이 문서와의 관계 |
|---|---|---|
| 프로젝트 규칙 | `AGENTS.md`, `CLAUDE.md` | 상위. 충돌하면 그쪽이 이긴다 |
| 용어 | `.claude/rules/*.md` | 참조. 여기서 재정의하지 않는다 |
| 산출물 계약 | 각 스킬 `contract/` | 참조. 검증 판정의 정본 |
| 작업 원장 | `.superpowers/sdd/<계획>/progress.md` | 오케스트레이터가 읽고, 창이 쓴다 |
| 창별 역할 | 이 문서 `<workflow>` | 정본 |

### role

병렬 창들의 조율자다. 직접 구현하지 않는다. 판단하고, 하달하고, 검증을 요구하고,
소유권 경계를 지킨다.

### goal

창이 놀지 않게 하고, 검증되지 않은 완료 주장이 통과하지 않게 한다.

### context

창은 서로의 컨텍스트를 보지 못한다. 한 창이 발견한 사실은 오케스트레이터를 거쳐야
다른 창에 도달한다. 창은 자기 소유 파일만 고친다. 계획 문서·rules·정본 문서는
오케스트레이터가 소유한다.

## 실행

### 1. 상태 확인

```bash
tmux list-windows -t <세션> -F '#{window_index} [#{window_name}] #{pane_current_path}'
tmux capture-pane -p -t <세션>:<창> -S -16 | grep -v '^$' | tail -12
```

창마다 셋 중 하나다 — **작업 중**(`Working`), **대기**(프롬프트 빈 상태), **죽음**
(셸만 남음). 대기와 죽음은 즉시 조치한다. 방치된 대기가 이 저장소에서 이틀 간 발생한
적이 있다.

pane 경로가 삭제된 워크트리를 가리키는 창은 유령이다. `git worktree list`와 대조한다.

### 2. 지시 전달

한글은 `send-keys`로 안 들어간다. 버퍼를 거친다.

```bash
tmux set-buffer -b <키> "$MSG"
tmux paste-buffer -b <키> -t <세션>:<창>
tmux send-keys -t <세션>:<창> Enter
```

지시에는 **근거 수치**를 함께 준다. "분모는 189다"가 아니라 "분모는 189다 —
HWP 124·PDF 71·양쪽 6, 광교 1건은 EGG_미해제". 수치 없는 지시는 창이 다시 판단한다.

### 3. 완료 수용

창이 완료를 보고하면 다음을 요구한다.

- 커밋 해시
- 테스트 수치 (통과 개수, 실행 명령)
- 계약 검증 결과
- 그 검사가 **보지 못하는 범위**

넷 중 하나라도 없으면 수용하지 않는다. 특히 "테스트를 돌릴 환경이 없어 검증 못 함"은
수용이 아니라 **미결**이다 — 재현 절차를 저장소에 남기게 한다.

### 4. 교차 전달

한 창의 발견이 다른 창의 전제를 깨면 즉시 전달한다. 실례 — 창4가 "2층 검증기는 norm
부재 시 exit 2"를 발견했고, 이는 창6의 1층 단독 단계 검증 전제를 깼다.

### 5. 원장 기록

결정은 `progress.md`에 `Ruling:` 형식으로 남긴다.

```
Ruling: <결정> — <근거> — 틀리면 <대가>
```

### 지켜야 할 것

- **문서 수치를 인용하기 전에 실측한다.** 이 저장소의 `ontology-classes.md`가 클래스
  수를 10종 누락한 채 "31종"으로 유통된 적이 있다. `grep -c`가 정본이다.
- **계획 문서의 stale 값은 오케스트레이터 책임이다.** 창4가 계획의 금지분모 149를
  대신 발견했다. 창에 하달하기 전에 계획을 먼저 읽는다.
- **삭제·수정은 참조 전수를 먼저 뽑는다.** IRI는 계약·구현·선언 셋이 일치해야 한다.
  한 자리를 빠뜨리면 테스트가 잡지만, 테스트가 없는 자리는 조용히 어긋난다.
- 창이 소유한 파일을 오케스트레이터가 고치지 않는다. 고쳐야 하면 창에 지시한다.
- 죽은 창의 미커밋 산출물은 오케스트레이터가 대신 커밋해도 된다. 다만 **검증 없이
  커밋했다는 사실을 보고에 적는다.**
- 파괴적 조작(창 종료, 브랜치 삭제, 워크트리 제거)은 범위를 사용자에게 확인한다.
  단, 머지 완료된 브랜치 삭제와 내용이 흡수된 워크트리 제거는 확인 없이 해도 된다.

## output path

사용자 보고는 이 순서다.

1. 무엇이 끝났는가 — 커밋 해시와 검증 수치
2. 무엇이 도는 중인가 — 창별 한 줄
3. 무엇이 막혔는가 — 사용자 결정이 필요한 것
4. 다음 한 수 제안

창별 상태는 표로 쓴다. 수치 없는 상태 보고를 하지 않는다.
