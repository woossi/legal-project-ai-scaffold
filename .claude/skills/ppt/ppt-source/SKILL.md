# ppt-source

## 구성

- `contract/source.schema.json` — `01_source.json` 의 구조 계약 (JSON Schema)
- `contract/outputs.json` — 선행조건·멱등성·값 도메인·교차 제약
- `scripts/measure.py` — 경로를 받아 행수·건수·바이트·sha256 을 세고 fact 후보를 낸다.
  **판단은 하지 않는다** — 무엇을 fact 로 승격할지는 에이전트가 정한다
- `references/자산-지도.md` — `output/{legal,kb,viz}` 의 계통별 위치와 쓰임.
  **수치를 적지 않는다** — 수치는 낡으므로 실행 시점에 센다

## 절대 규칙

### 1. 수치는 실행 시점에 직접 센다

`meta` 블록·요약표·남이 만든 리포트의 숫자를 그대로 옮기지 않는다. 원본 파일을 열어
센다. 이 저장소에는 요약이 갱신 전 값이었던 이력이 여러 건 있다.

`fact` 의 `measured_by` 에 **어떻게 셌는지**를 적는다. `"CSV 헤더 제외 행수"`,
`"JSON 최상위 배열 길이"` 처럼 재현 가능한 문장이어야 한다.
`locator`에는 검증기가 같은 값을 다시 계산할 위치를 적는다. JSON은 RFC 6901 pointer를
사용한다. CSV·JSONL·파일 크기는 `measure.py`가 정의한 `@` locator를 사용한다.

### 2. 분모를 값과 분리해 적는다

비율·백분율을 fact 로 만들 때 `denominator` 를 별도 필드로 둔다. 분자만 있는 fact 로
비율을 만들지 않는다. 이 프로젝트는 모수가 갈리며 분모 왜곡으로 결론이 뒤집힌 이력이 있다.

같은 대상에 분모가 둘 이상이면 **fact 를 둘 발급한다.** 하나에 합치지 않는다.

### 3. 시점·필터가 다른 자산을 한 fact 로 합치지 않는다

산출 시점이 다르거나 필터 조건이 다른 두 파일의 수치는 서로 다른 fact 다.
`as_of` 와 `caveat` 로 구분한다. 값이 비슷하다는 이유로 하나로 묶지 않는다.

### 4. sha256 을 반드시 남긴다

`sources[].sha256` 은 하류(`ppt-writer`·`ppt-verifier`)가 상류 갱신을 감지하는
유일한 수단이다. 빠뜨리면 낡은 수치가 조용히 덱에 남는다.

### 5. 표본을 전체로 일반화하지 않는다

일부 산출물은 소수 문서 표본이다. 표본이면 `caveat` 에 표본 규모와
"전체 성능으로 일반화 불가"를 적는다.

## 실행

1. **덱 대상을 확인한다.** 어떤 작업을 정리하는 덱인지 호출자에게 받는다.
   기본 범위를 고정하지 않는다.
2. **자산을 훑는다.** `references/자산-지도.md` 로 계통을 잡고 실제 경로를 확인한다.
   지도에 없는 새 산출물이 있으면 보고 항목에 경로를 남긴다. 자산 지도 수정은 별도
   스킬 유지보수 작업에서 수행한다.
3. **`sources[]` 를 등록한다.** 경로·소유팀·형식·sha256·`contract_status`.
   `contract_status` 는 그 산출물에 계약 검증기가 있고 통과했는지다 —
   모르면 `unknown` 으로 두고 추정하지 않는다.
4. **`facts[]` 를 발급한다.** 규칙 1~5 적용. `scripts/measure.py` 로 세고 재측정용
   `locator`를 함께 적는다. 덱에 쓰이지 않을 수치까지 다 넣지 않는다.
5. **한계를 적는다.** `limitations[]` 에 이 덱이 말할 수 없는 것을 적는다.
   미검증 항목·미해결 과제·표본 한계.
6. **센 결과를 보고한다.** fact 건수, 분모가 붙은 fact 건수, `unknown` 계약 건수.

## output path

`output/ppt/<deck-id>/01_source.json` 하나만 쓴다.
`output/{legal,kb,viz}` 를 **읽기만** 한다. 상류 산출물을 고치지 않는다.
