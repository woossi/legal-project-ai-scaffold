목차구조 전수조사에서 실제로 틀렸던 것들을 적는다. 같은 함정이 다음 배치에서도 그대로
재현되므로, 규칙보다 이 기록이 값지다.

# 필터가 정상 케이스를 배제했다

## 길이 상한이 편 표제를 잘랐다

본문 문장이 헤딩으로 잡히는 것을 막으려고 `real_heading()` 에 "제목 45자 초과면 배제"를
넣었다. 그런데 편 표제는 관할 용지를 나열하느라 100자를 넘긴다.

```
# 제2편 건축부문 시행지침 : 단독주택용지, 근린생활시설용지, 공동주택용지, 상업시설용지, 공공건축물 및 기타시설용지
```

정상 편 헤딩이 통째로 배제되어 4개 문서가 "구조 없음"에 가깝게 판정되었다. 그 상태로 한
라운드 보고까지 나갔다. 이 실패가 전수조사에서 가장 컸다.

- 표면 지표(길이·글자수)로 의미 판정을 대신하지 않는다. 문서 종류마다 분포가 다르다
- 필터를 넣기 전에 걸러낼 대상을 전수로 뽑아 눈으로 확인한다. 45자 초과가 37건뿐이었고
  표제 24건과 문장 8건으로 깨끗이 갈렸다. 5분이면 확인되는 양이었다
- 대안은 의미 신호이다. 명사구 종결과 용언 종결을 가른다

교정 시도에서도 틀렸다. 용언 종결을 잡겠다고 단음절 조사(`로`·`이`·`가`)를 넣었더니
도로·통로·진입로가 문장으로 오인되어 21건이 잘못 움직였다. 서울신내3은 7에서 1로
붕괴하였다. 한국어 명사 어미와 조사는 겹치므로 다음절 확정 표현만 쓴다.

## "A이고 B" 강화 조건이 문서를 놓쳤다

병합 구분자만 있는 파일이 부문으로 잡히는 것을 막으려고 "부문 헤딩 2개 이상 그리고 하위
헤딩 존재"로 조건을 걸었다. 구리갈매는 하위가 전부 유실되어 탈락하였고, 최하위 분기인
"무헤딩형"으로 떨어졌다.

방어 조건이 정상 케이스를 배제하지 않는지 확인한다. 특히 B 가 유실될 수 있는 데이터이면
A 만으로 충분한지 다시 본다.

# 계층 신호를 잘못 읽었다

## 목차와 본문이 둘 다 본문량 0 이라 중복 판정이 발동하지 않았다

"앞선 중복이면서 본문량이 더 적으면 목차"라는 규칙을 썼다. 그런데 편 헤딩은 바로 다음 줄이
장 헤딩이라 본문량이 0 이다. 목차본과 본문본이 0 대 0 으로 동점이 되어 규칙이 걸리지 않았고,
시흥장현·성남고등·서울양원이 "본편+별책 2블록"으로 오독되었다.

해결책은 자식에서 부모로 전파하는 방식이다. 하위 장이 전부 목차로 판정된 편 헤딩은 그
자신도 목차로 본다. 부모 노드의 신호가 약하면 자식 노드에서 올린다. 계층 데이터에서
반복되는 패턴이다.

# 원문을 안 보고 판정했다

## 대표 사례로 제시한 문서가 반례였다

유형표에서 "헤딩 전무형"의 대표 지구 첫 번째로 영종하늘도시를 썼다. 그런데 그 문서에는
헤딩이 57개 있었고, ZIP 분책 파일명(`# 02(별첨)_제1장_계획의개요…`)에 장 구조가 보존되어
있었다. 대표 사례가 그 유형 정의의 반례였다.

유형표의 대표 지구는 반드시 실물을 열어 확인한다. 자동 분류가 뽑아준 상위 N건을 그대로
쓰면 이런 결과가 나온다. 검수자가 가장 먼저 보는 것도 대표 사례이다.

두 번째 라운드에서도 반복할 뻔했다. 규칙 개선으로 과천주암·남양주왕숙2가 `편 다중블록형`
에서 빠져나가 대표가 비었는데, 없는 세 번째를 끌어오지 않고 "해당 2건 전부"로 표기하려
하였다. 이후 신규 회수분이 들어와 3건이 채워졌다.

## 자동 판정을 그대로 믿었으면 틀렸을 것들

- **시화MTV** — 한 md 에 141행 `총4편` 과 2116행 `총5편` 두 선언이 있었다. 첫 번째만 보면
  "CSV 의 5는 과대계상"이라는 지적이 맞는 것처럼 보인다. 실제로는 시흥시분 4편과 안산시분
  5편이 병합된 문서였다
- **안산신길2** — 편 헤딩이 5개뿐이라 "6은 틀렸다"는 지적이 왔다. 129행 열거형 구성선언,
  원본 파일명 `…시행지침(5편_6편)`, 본문 50여 회 참조로 6이 맞음을 입증하였다

판정값이 도전받으면 원문으로 간다. 요약본이나 중간 산출물로 답하지 않는다.

# 도구 사용

## 모듈 import 만으로 산출물을 덮어썼다

디버깅하려고 `analyze.py` 를 import 했는데 실행부가 모듈 레벨에 있어 CSV 가 통째로
덮어써졌다. 당시는 모수 확정 전이라 갱신 금지 지시가 있던 상태였다. 파일별 분석이
독립적이라 신규 행만 제거해 원상 복구하였고, 값 전수 일치를 확인하였다.

- 산출물을 쓰는 스크립트에는 반드시 `if __name__ == '__main__'` 가드를 건다
- 지시받은 금지사항("아직 덮어쓰지 마라")은 도구 사용 방식에서도 지킨다
- 사고는 숨기지 않고 먼저 보고한다. 복구 근거(값 일치 확인)를 함께 제시한다
