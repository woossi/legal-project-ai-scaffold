# 요약을 그대로 옮김

`terms.json` 의 `meta.추출정의문수_총` 은 7,326인데 원자료 세 경로(`occurrences` 배열
길이·`occurrence_count` 필드·`variants[].count`)가 모두 7,325다. 개별 데이터는 온전하다 —
`occurrence_count ≠ len(occurrences)` 인 용어도, `doc_frequency ≠ 지구 고유 수` 인
용어도 0건이다. **총계 요약만 1건 많다.**

같은 7,326이 `core_terms.json` · `taxonomy.json` · `_extraction_report.json` 의 `meta`
에도 복사돼 있다. 요약을 옮기면 오차가 파일 수만큼 번진다.

# 분모를 바꿔 세고 같은 등급이라 부름

`ubiquity` 등급을 분모 189로 다시 세면 코어가 3개, 165로 세면 5개다. 데이터에 실린
값은 5개이며 임계에 걸린 것은 불허용도(132/189 = 0.698)와 전면도로(121/189 = 0.640)다.
**등급 이름이 같아도 분모가 다르면 다른 판정이다.** 상세는 `case/모수왜곡.md`.

`taxonomy.json` 의 `axis_D.설명` 이 분모를 189로 적었으나 실린 분포를 재현하는 분모는
165다. 설명 문구를 믿고 다시 그리면 코어가 3개가 된다.

# 이름이 같은 필드를 나란히 비교

`정의조항_보유문서수` 는 `_extraction_report.json` 에서 166, `doc_definitions.json`
에서 161이다. 판정 규칙이 다르며 각 파일은 자기 안에서 정합하다. 한 표에 나란히
올리면 5건이 결손처럼 읽힌다. `재계산필드` 에 판정 규칙과 함께 둔다.

`시행지침_재검증_리포트.json` 이 이미 같은 결론을 냈다 — "결함아님, 지표정의차이".

# 기록 파일의 상태 문자열을 집계 근거로 씀

`legal-textreform/case/_failed.json` 은 효행지구를 "적재하지 않고 실패로 남김" 으로
적었으나 md 는 실제로 적재돼 있다. `OCR_적재` 는 2건만 기록하는데 산출물에서
`source_quality: OCR` 을 다시 세면 3건이다.

기록은 갱신되지 않을 수 있다. **상태 문자열이 아니라 산출물의 필드를 센다.**

# 저장소 밖 원본을 파일 실재로 검사

원본 hwp·pdf 는 `.gitignore` 로 워크트리에 체크아웃되지 않는다. 워크트리에서 수집
계약을 파일 실재로 검사하면 **전량이 위반으로 나온다** — 서울 38건 검사 중 37건 위반,
인천 22중 21, 경기 133중 132(`시행지침_재검증_리포트.json`
`A_수집완결성.verify_contract_dup_워크트리기준_참고`). 개별 손상이 아니라 검사 환경
문제이며, 메인 체크아웃에서 다시 돌려 위반 0건임이 확인됐다.

그래서 S2 는 파일 실재가 아니라 `meta.json` 의 다운로드 기록을 센다. **이 집계는 기록은
있는데 파일이 깨진 경우를 보지 못한다** — 사각지대로 명시한다.

# 이 집계를 만들며 마주친 것

아래는 실제로 데인 사례가 아니라, 이 스킬을 만들며 빠질 뻔한 자리다. 근거를 밝혀 둔다.

## 수집 대상 분모를 실패율로 읽음

S1 은 `190/543` 이다. 택지정보시스템 스캔 543지구 중 시행지침 첨부가 있는 것이 190이라는
뜻이지, 353건 수집에 실패했다는 뜻이 아니다. 비율만 떼어 "35% 수집" 으로 옮기면
실패율로 읽힌다. 첨부가 없는 지구는 결손이 아니라 대상 밖이다.

`분모_정의` 에 "무엇을 센 분모인지" 를 적는 이유가 이것이다.

## 같은 수를 같은 모수로 봄

156은 `viz-chart.md` 의 구 추출 성공 모수이기도 하고, `statute_citations.json` 의
인용 간선이 붙은 지구 수이기도 하다. 우연히 같다. 섞으면 인용 간선 커버리지가
`156/156 = 100%` 로 보인다. 올바른 값은 `156/165 = 94.5%` 이며, 실측으로 정의문은
있으나 간선이 붙지 않은 지구가 9곳이다.

## 제외 시 수치에서 분자·분모를 같은 수로 깎음

S4 의 OCR 유래는 분자에서 2건, 분모에서 3건이다. 효행지구는 md 는 OCR 로 적재됐으나
정의문이 0건이라 분자에 애초에 없다. 분자 쪽 2건으로 분모까지 깎으면 모수가 187이
되어, 전수조사가 쓰는 OCR 제외 모수 186과 어긋난다. 올바른 값은 `163/186` 이다.

**격리 건수는 단계마다 다시 센다.** 앞 단계의 건수를 그대로 물려받지 않는다.

## 못 센 것을 0으로 적음

prob 층 ttl 이 아직 없다. 0건으로 적으면 "판정층을 만들었는데 비었다" 는 뜻이 되어
사실과 다르다. `미집계` 이며 실패가 아니다 — `프로젝트-설계구조.md` 의
**미검사(skipped)** 와 같은 취급이다.
