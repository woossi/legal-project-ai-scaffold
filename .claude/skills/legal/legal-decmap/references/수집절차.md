# legal-decmap — 수집 절차

실행기는 `legal-dup/scripts/collect.py` 다. 이 문서는 **도면 첨부에 한정한 절차와 판정**을
적는다. 엔드포인트·시도 코드·`fileRegistNo` 의 정본은 `legal-dup/case/reference.md` 다.

`BLS5_DSTRC_MASTER`는 지구단계정보 원장이고 도면 첨부를 포함하지 않는다. 이 파일은
`legal-dup/scripts/collect_master.py`가 별도 스냅샷으로 보존한다. 아래 첨부 API 사슬과
`output/legal/시행지침/meta.json`은 그대로 유지한다.

## 0. 착수 전 확인 셋

```bash
MAIN="${LEGAL_PROJECT_ROOT:-$(git rev-parse --show-toplevel)}"

# ① 원본 190건 — 작업 전후로 같아야 한다
find $MAIN/output/legal/시행지침 -type f \( -name '*.hwp' -o -name '*.pdf' -o -name '*.zip' \) | wc -l

# ② _index.json 선행 — 셋 다 있어야 fetch 가 돈다
ls $MAIN/output/legal/시행지침/*/_index.json

# ③ 이름 규약이 고쳐졌는가 — 안 고쳤으면 코드 5 를 받지 않는다
grep -n "ASSET_STEM" $MAIN/.claude/skills/legal/legal-dup/scripts/collect.py
```

## 1. API 사슬

`legal-dup` 이 소유한다. 직접 호출하지 말고 `collect.py` 를 쓴다.

```
① POST map.jigu.go.kr/search/moreResultDstrc.json      지구 목록
② POST map.jigu.go.kr/dstrc/dstrcInfo.do (detailInfo)   첨부 목록
③ GET  openapi.jigu.go.kr/file/dstrcFileDownload.json   다운로드
       ?jobSe=dstrc&fileCode=<코드>&fileRegistNo=<타입>
```

**엔드포인트가 둘이라는 것이 과거 정정 사항이다.** 화면은 `dstrcDetailInfo.do`(`dstrcHistNo`)
도 호출하며 거기에만 코드 1 고시문이 있다. `detailInfo` 만 보고 "첨부 누락 없음"이라 판정한
이력이 있으니 첨부 모수를 말할 때 어느 엔드포인트 기준인지 밝힌다.

## 2. 실행

```bash
MAIN="${LEGAL_PROJECT_ROOT:-$(git rev-parse --show-toplevel)}"
C=$MAIN/.claude/skills/legal/legal-dup/scripts/collect.py

python3 $C fetch --region 경기 --file-type 5      # 표본 판정 후에만 전수로
python3 $C fetch --region 서울 --file-type 5
python3 $C fetch --region 인천 --file-type 5
python3 $MAIN/.claude/skills/legal/legal-dup/scripts/verify_contract.py
```

- `--region` 은 `서울`·`인천`·`경기` 셋뿐이다
- `--file-type` 은 `fileRegistNo` 콤마 구분이다. `2,4,5` 를 함께 받아도 된다
- **멱등이다.** `meta.json` 의 `savedAs` 가 가리키는 파일이 존재하고 크기가 0 이 아니면 그
  첨부는 다시 받지 않는다. 중단되면 같은 명령으로 재개한다
- 지구 1건마다 `meta.json` 을 재기록하므로 중단해도 그때까지의 결과가 계약을 만족한다

## 3. 표본 설계

전수 전에 값하는지 판정한다. 표본은 **지구 5~8** 이고 다음을 고른다.

- 시도 셋을 모두 포함한다 — 서식 관행이 시행자 단위로 갈린다
- 미치환 라벨이 많은 지구를 우선한다 — 값이 있어야 판정에 의미가 있다
- 이미 결정도를 가진 지구(`41390LH2024001` 시흥정왕, `41390KW2017001` 반월)를 하나 넣어
  **대조군**으로 쓴다. 그 둘은 벡터 PDF 라 라벨이 텍스트로 나온다

재는 것과 판정 기준은 `contract/decmap.json` 의 `착수판정` 이 정본이다.

## 4. 받은 뒤

형식 판별과 라벨 추출은 이 순서가 값싸다.

```bash
pdfimages -list <pdf>            # 래스터/벡터 판별. 이미지 0건이면 벡터다
pdftotext -bbox <pdf> out.html   # 벡터면 여기서 라벨이 나온다. pdfplumber 보다 안정적이다
```

래스터면 이미지를 꺼내 이어붙인 뒤 OCR 한다. `tesseract -l kor+eng --psm 11` 과 `--psm 12`
를 모두 시도하고 `tsv` 로 받아 신뢰도와 bbox 를 보존한다.

**본도와 범례를 갈라야 한다.** 도곽 안 본도 영역으로 자르지 않으면 범례 라벨이 개체로
섞인다. 실측에서 가구·획지 코드 8건 중 3건이 범례였다.

## 5. 산출

- 원본은 `output/legal/시행지침/<지역>/<지구명>/` 에 바이트 그대로. 변형은 하류의 몫이다
- 판정 문서는 `output/legal/lot-zone-audit/` 에 둔다
- 판정 문서에는 지구별 **형식·축척·실효 DPI·라벨 판독 성공률**과 **미치환 라벨과의 겹침**을
  적는다. 검출("OCR 이 읽었다")과 판정("그 라벨이 획지다")을 구분해 적는다
