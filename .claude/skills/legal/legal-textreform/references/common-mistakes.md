사례 파일은 `case/_failed.json` 이다. 게이트 예외는 같은 파일의 `게이트예외적용` 항목에
기록한다. 구 `_gate_exceptions.json` 은 이 파일에 병합되었다.

# 압축 해제

## 매직바이트를 먼저 확인한다

`xxd -l 4 -p <파일>` 로 매직바이트를 읽는다. `504b0304` 는 ZIP, `45474741` 은 EGG,
`d0cf11e0` 는 HWP5(CFB), `%PDF` 는 PDF 이다.

확장자가 `.zip` 인데 매직이 `EGGA` 인 EGG 아카이브가 있다. 표준 `zipfile` 과 `unzip` 은 이
파일을 열지 못한다. `unegg` 나 `egg` 계열 도구가 없으면 회수할 수 없으므로, 억지로 시도하지
말고 `case/_failed.json` 에 남긴다.

ZIP 내부는 편별로 쪼개져 있고 2중 ZIP 도 있다. 부천역곡은 zip 안에 zip 이 있고 그 안에 hwp
4개가 들어 있다. 한 지구가 단지별로 갈리기도 한다. 고양창릉은 zip 안이 `본단지/` 와
`기업이전단지/` 로 나뉜다.

## ZIP 파일명 mojibake

UTF-8 플래그(`flag_bits & 0x800`)가 꺼져 있으면 파일명이 깨져 있다.
`filename.encode('cp437').decode('cp949')` 로 복원하되, `cp437` 이 실패하면 `latin-1` 로
재시도한다.

```python
def decname(info):
    if info.flag_bits & 0x800: return info.filename
    for enc in ('cp437','latin-1'):
        try: raw = info.filename.encode(enc)
        except Exception: continue
        for d in ('cp949','euc-kr','utf-8'):
            try:
                s = raw.decode(d)
                if s and '\ufffd' not in s: return s
            except Exception: pass
    return info.filename
```

## pyhwp 는 six 없이 조용히 실패한다

pyhwp 만 설치하면 `hwp5txt` 전 경로가 "빈 결과"로 실패한다. 게다가 traceback 을 출력하면서
종료코드 0 을 반환한다. rc·파일 존재·글자수로 성공을 판정하면 안 되는 이유가 여기에 있다.
부천역곡 HWP 4건이 이 문제로 전부 실패했다가 `six` 와 `olefile` 설치 후 회수되었다.

```
python3 -m venv .venv_hwp

export HWP5TXT=<프로젝트>/.venv_hwp/bin/hwp5txt   # scripts/convert.py가 이 경로로 도구를 찾는다
```

도구가 동작하지 않으면 다른 세션의 venv 가 살아 있을 수 있으므로 `find / -name hwp5txt` 로
대안을 찾는다.

# 절삭

## 표 절삭이 조문을 지운다

절삭 후 조문 항목이 사라지면 게이트가 `조문수 감소` 또는 `조문항목 규범수치 감소` 로
잡는다. 원인은 표 블록의 여는 조건(다중공백 행 2연속)이 헤딩·조문항목 행에서도
우연히 성립하는 데 있다. 밀도 게이트가 걸러내야 하지만 블록에 단문이 많으면 밀도가
60% 를 넘어 통과한다. 실측 사례 — `#### 제 15 조  건폐율 완화` 는 `조  건` 부분의
다중공백 때문에 여는 줄이 됐고, 뒤따르는 `- ①` 조문항목도 다중공백을 포함해 닫는
조건(`다중공백 없음`)이 발동하지 않아 조문 전체가 삼켜졌다.

임계값을 낮추는 것으로는 부족하다 — 닫는 조건만 손보면 조문항목 자체에 다중공백이
있을 때 애초에 발동하지 않는다. **여는 조건에서 헤딩·조문항목 행을 막는 것**이
정확한 대응이다. 표 안의 셀도 `- ①` 로 시작할 수 있으므로 이 배제는 여는 조건에만
걸고 닫는 조건은 그대로 둔다. 실측: 헤딩이 연 블록 23개(조문 헤딩 22개) ·
조문항목이 연 블록 195개(1,033행) — 수정 후 전부 0.

## 페이지 푸터 패턴이 표의 수치 셀을 지운다

푸터 패턴을 `^\s*-?\s*\d+\s*-?\s*$` 처럼 느슨하게 잡으면 표 안의 `324` 같은 단독
수치 행까지 페이지 푸터로 오인해 지운다. 양쪽 하이픈이 있는 `- 48 -` 형태로
한정한다(`PAGE_FOOT = r"^\s*-\s*\d{1,4}\s*-\s*$"`). 페이지번호만 있는 푸터(`48`)는
표 수치와 구분할 수 없으므로 남긴다.

## merge_md.py 재실행이 절삭을 되돌린다

절삭했는데 표 잔해가 다시 나타나면 원인은 대부분 이것이다 — 절삭은 병합 md 의
후처리이고, `merge_md.py` 는 원본 txt 에서 병합 md 를 다시 만든다. 병합 → 승격 →
절삭 → 계약검증 순서를 지킨다. 승격과 같은 제약이다.
