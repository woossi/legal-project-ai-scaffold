# 검증기 통과는 안전 보증이 아니다

이 스킬을 만들면서 판정을 **네 번** 고쳤다. 네 번 모두 **계약 검증이 통과를 보고하는
상태**에서 나왔다. 산술은 완벽했고 구조 계약도 맞았다. 틀린 것은 판정 규칙이었다.

`.claude/rules/프로젝트-설계구조.md` §5 의 **자기 일관성** — "같은 스크립트가 만든 두
파일이 서로 맞는 것. 검증이 아니다" 가 이 문서의 요지다. 아래 넷은 그 추상적 경고가
실제로 어떤 모습으로 나타났는지의 기록이다.

찾아낸 방법은 셋뿐이었다 — **교차표**, **위반 심기**, **원문 대조**. 검증기를 다시 읽는
것으로는 하나도 찾지 못했다.

---

## 1. 모수 혼동 — 단위가 다른 값을 max 로 비교했다

`loss_class` 의 지배값을 `loss_mix` 의 건수 최대값으로 정했다. 그런데 갈래마다 세는
단위가 달랐다.

```
loss_mix = {'값깨짐': 4, '소실없음': 4, '표자체없음': 45}
              값 줄 개수    값 줄 개수     표 개수      ← 단위가 다르다
```

frontmatter 표 수가 최대 270이라 **표를 많이 선언한 문서는 값이 살아 있어도 무조건
`표자체없음`** 이 됐다. 서울신내2는 값 8줄이 있는데 표 45개에 밀렸다.

| 증상 | 값 보유 93문서 중 **84문서**가 `표자체없음` 으로 분류 |
|---|---|
| 검증기 | 14/14 통과. `loss_class` 가 `loss_mix` 의 키인지는 검사했다 |
| 발견 | `값줄수>0 × loss_class` **교차표**를 떠서 |
| 고침 | 건수 max → 값 회수 상태 우선순위. `loss_mix` 키에 단위 표기(`표자체없음_표건수`) |

**교훈** — 이름이 같은 필드를 나란히 놓으면 비교하게 된다. 단위가 다르면 이름에 단위를
박아라. 그리고 분포가 한쪽으로 쏠리면 판정 규칙을 의심하라.

## 2. 지배값 선정 — 다수결이 결함을 가렸다

`article_integrity_class` 를 codex 의 문서별 카운트에서 최빈값으로 뽑았다.
`complete_count` 가 거의 항상 최대라서 결함이 있는 문서도 `완전` 이 됐다.

| 증상 | max 로 뽑으면 **104문서가 `완전`**. 실제 결함 없는 문서는 21건 |
|---|---|
| 검증기 | 통과. 분포 합이 189로 맞았다 |
| 발견 | codex 원자료에서 **독립 재계산**해 대조 |
| 고침 | 결함 우선순위 판정(구조누락 > 본문누락 > 순서훼손 > 완전). 원본·md 양쪽 조문이 0개인 문서는 `조문없음` 으로 `완전` 과 분리 |

**교훈** — 다수결은 결함 탐지에 쓰지 않는다. 정상이 다수인 것이 정상이라서, 최빈값을
쓰면 결함이 구조적으로 가려진다. **합이 맞는 것은 분류가 맞다는 뜻이 아니다.**

## 3. 근거 강도 미분리 — 약한 판정이 강한 것과 같은 자격을 얻었다

관계 필드 5건을 발급하면서 `relation_basis` 를 전부 `동일줄_수식어명시` 로 뒀다.
그중 하나는 근거가 질적으로 달랐다.

```
기준용적률은 …(제2종일반주거지역, 200%)로 하며      ← 구문상 직접 수식
(평균용적률 / 기준용적률) = (130.0% / 180.0%)      ← 나열 순서로 위치 귀속
                                     basis 가 둘 다 같았다
```

강도 차이는 `relation_note` 자유 텍스트에만 있었다. **하위 축이 `relation_basis` 로
필터링하면 약한 근거가 강한 것과 같이 들어온다.** 자유 텍스트는 기계 필터가 아니다.

| 증상 | 관계 필드를 붙인 목적(하위 축이 구별)이 절반만 달성 |
|---|---|
| 검증기 | 통과. 근거 발췌가 원문에 실재하는지는 전수 검사했다 |
| 발견 | 발급 5건을 **원문 대조**하다 근거의 성격이 다름을 봄 |
| 고침 | `동일줄_직접수식`(4) · `동일줄_순서대응`(1) 로 분리. meta 에 `약한근거` 목록 |

**교훈** — 저신뢰 플래그는 **기계가 거를 수 있는 필드**여야 한다. 서술로 적어두는 것은
기록이지 플래그가 아니다.

이때 **계약만 고치고 구현이 안 따라온** 중간 상태도 나왔다. 계약과 SKILL.md 는 새 값인데
판정표가 옛 값을 하드코딩한 채였다. 계약을 고쳤으면 **판정표·산출물·검증기까지 한
라운드에** 넣어라. 계약에 `검사방법` 을 적고 게이트를 구현하지 않으면 통과 보고가
거짓 안심을 준다.

## 4. 값의 자격 — 원문에 실재하지만 규범이 아닌 값

가장 늦게 발견됐고 가장 컸다. 도면 표시 **예시도** 안의 값이 규범값으로 실려 있었다.

```
**<그림 2-1-1> 지침내용 도면 표시 예시도**
용적률 : 180% 이하        ← 이 지구가 180% 라는 뜻이 아니다
                            "이렇게 표기한다" 는 설명이다
```

원인은 둘이었다. 캡션 탐지가 `<표>` 만 잡고 **`<그림>` 을 안 잡았다**(원문 캡션은 표
3,769 · 그림 4,508 로 그림이 더 많다). 그리고 예시 판정이 "앞 6줄" 로 제한돼 캡션이
더 위면 놓쳤다.

| 증상 | 규범 1,683 중 **460건이 예시도 값**. `예시도면표시` 로 잡힌 건 12건뿐이었다 |
|---|---|
| 검증기 | 통과. surface 가 원문 line·offset 에 실재하는지 1,910건 전수 검사했다 |
| 발견 | **외부 제보** — 하위 축(용지 조사)이 자기 모수 321건 중 78건이 예시도 소재임을 관찰 |
| 고침 | `<그림>` 캡션 탐지 추가, 구간 판정(`example_zone`) 도입. 규범 1,683 → **1,223** |

**교훈** — 값 실재 검사는 **자격**을 보지 않는다. 숫자가 원문에 있다는 것과 그것이
규범이라는 것은 다른 주장이다. 이 유형은 환각 검사·불변식 검사·구조 계약을 전부
통과한다.

### 자격 문제를 넓힐 때의 함정

예시 어휘를 넓게 잡으면 반대 방향으로 틀린다. `계획도`·`개념도`·`위치도`·`구상도` 를
넣어 전수 확인했더니 추가로 걸린 14건이 **전건 실제 규범**이었다.

```
**<그림Ⅳ-2-17> 산림조망권역 경관계획도**
  - 용지별 도시건축사항
규     건폐율    30% 이하    60% 이하      ← 캡션은 "계획도" 지만 내용은 규범표
```

구간 경계도 같다. 캡션 아래를 다음 캡션까지로 잡으면 실제 조문을 삼킨다. **heading ·
다음 캡션 · 조항 항목 · 공백 2줄** 중 가장 이른 것에서 끊어야 한다.

## 5. 값의 자격 2차 — 유형은 다섯을 셌는데 실제로 나온 건 셋이었다

#4 를 고친 뒤 같은 계열이 더 있는지 2차로 뒤졌다. 가설은 다섯이었다 — 상위법령 인용 ·
현황/기정 · 삭제/개정 이력 · 타 지구 참조 · 산식/예시 계산.

**결과가 가설과 어긋났다.** 어휘 적중은 있었지만 원문 대조에서 대부분 규범이었다.

| 가설 유형 | 어휘 적중 | 실제 분리 | 왜 |
|---|---:|---:|---|
| 상위법령 인용 | 63 | **1** | 62건이 조례를 근거로 든 **이 지구의 규범**이다 |
| 현황·기정 | 8 | 0 | `기정` 은 조서 표의 **열 머리**라 값이 안 딸려 온다 |
| 삭제·개정 이력 | 4 | 4 | 실제로는 이력이 아니라 **예시 도해**였다(아래) |
| 타 지구 참조 | 0 | 0 | 없다 |
| 산식·예시 계산 | **0** | **2** | 내 수동 조사가 놓쳤고 **게이트가 잡았다**(아래) |

### 인용은 근거 제시이지 자격 박탈이 아니다

가장 위험한 것이 (1)이었다. 인용 어휘를 정규식으로 걸었다면 규범 62건이 뒤집힌다.

```
규    범  「과천시 도시계획 조례」에 의거 당해 토지 건폐율 ∙ 70% 이하
규    범  「서울시 도시계획조례」제55조 제4항에 따라 용적률 250% 이하로 계획하여야 한다
인용서술  「안성시 도시계획조례」상 제2종일반주거지역의 용적률은 250%이하로 규정하고 있음
```

가르는 것은 어휘가 아니라 **주어와 서술어**다. 주어가 이 지구고 서술어가 `적용·의거`
면 규범, 주어가 인용 법령이고 서술어가 `규정하고 있음` 이면 그 법령의 내용 서술이다.
그래서 발급을 판정표(`CITATION_DESCR`)로 고정했다 — 관계 필드와 같은 이유다.

### 마커를 줄로만 읽고 구간을 안 열면 다음 줄을 놓친다

(3)으로 걸린 4건은 이력이 아니라 **#4 와 같은 결함의 잔여**였다.

```
- ④ … 건폐율, 용적률, 최고층수는 다음과 같이 표기한다.
예)                                 ← 캡션 참조가 없어 구간을 못 열었다
⇒ 용적률 400%이하, 건폐율 60%이하     ← 규범으로 실려 있었다
```

`예)` 는 값 줄 판정 어휘에는 있었지만 **구간을 여는 캡션으로는 인정되지 않았다** —
구간 개시 조건이 `<그림…>`·`<표…>` 참조뿐이었기 때문이다. 그래서 상계 장암 59줄은
마커가 값 줄에 같이 있어 잡혔는데 **바로 다음 줄 61줄은 규범으로 남았다.**
`<그림>` 을 안 보던 #4 의 결함과 **정확히 같은 구조**다: 어휘는 맞았고 적용 단위가
틀렸다.

| 증상 | 같은 예시 블록 안에서 59줄은 예시, 61줄은 규범 |
|---|---|
| 검증기 | 게이트 22·23 통과. 구간을 같은 조건으로 세었으니 자기 일관성이었다 |
| 발견 | 규범 1,223 을 어휘로 훑고 **걸린 건을 전건 원문에서 눈으로** 봄 |
| 고침 | `EXAMPLE_DECL_LINE` 으로 줄 전체 예시 선언도 구간을 열게 함. 5건 재분류 |

### 내 수동 전수 조사가 놓친 것을 게이트가 잡았다

(5)를 나는 **0으로 보고할 뻔했다.** 규범 1,223 을 훑을 때 `context_class == 규범`
필터를 **확정 파일에만** 걸었기 때문이다. 실제 건은 격리 쪽에 있었다.

```
격리 V000444 규범  예를 들어, 법상 건폐율의 최대한도가 60%이고 도시ㆍ군계획조례는
                  50%로 정하고 있는 경우 …        ← 수립지침 훈령 3-2-4. 전재
```

새로 넣은 게이트 25 가 확정·격리를 **둘 다** 훑어 2건을 잡아냈다. 게이트를 넣은
그 라운드에 게이트가 자기를 만든 사람의 누락을 잡은 것이다.

**교훈** — 조사 모수를 확정에만 걸면 격리가 안 보인다. `확정 + 격리 = 관측` 은
소비 계약일 뿐 아니라 **조사 모수의 규약**이기도 하다.

또 하나 — 판정표 키를 offset 34 대신 30 으로 **눈대중해 적었더니** 재분류가 조용히
0건이 됐다. 정규식이었다면 근처 아무 값이나 잡아 뒤집혔을 것이다. **판정표는 키가
안 맞으면 아무 일도 안 일어나서, 결과 건수를 확인하지 않으면 못 알아챈다.**

# 이 다섯에서 나온 검사 규칙

1. **분포가 한쪽으로 쏠리면 판정 규칙을 의심한다.** 84/93, 104/189, 460/1683 이 전부 그랬다
2. **교차표를 떠라.** 한 축의 분포만 보면 안 보인다. `값보유 × loss_class` 처럼 두 축을 걸어라
3. **위반을 심어 게이트가 잡는지 확인하라.** 통과만 보고하는 것은 검증이 아니다.
   이 스킬은 누적 23종을 심어 확인했다
4. **원자료로 독립 재계산하라.** 추출기가 쓴 필드로 검산하면 자기 일관성이다.
   `example_zone` 검사는 필드를 세지 않고 md 원문에서 구간을 다시 계산한다
5. **저신뢰는 기계가 거를 수 있는 필드로 남겨라.** 자유 텍스트 서술은 플래그가 아니다
6. **계약을 고치면 판정표·산출물·검증기를 한 라운드에 맞춰라**
7. **값이 실재한다와 값이 자격을 갖췄다를 구분하라.** 후자는 별도 검사가 필요하다
8. **넓히는 수정은 반대 방향 오류를 만든다.** 넓힌 뒤 추가로 걸린 것을 전건 원문 확인하라
9. **어휘가 걸렸다는 것은 유형이 있다는 뜻이 아니다.** 2차 조사에서 어휘 적중 75건 중
   실제 분리는 8건이었다. **적중을 전건 원문 대조하고, 그 어휘가 붙었는데 규범인
   사례를 먼저 찾아라** — (1)은 63건 중 62건이 반례였다
10. **조사 모수를 확정에만 걸지 마라.** `확정 + 격리 = 관측` 은 소비 계약이자
   **조사 모수의 규약**이다. 격리만 훑었으면 나왔을 2건을 수동 조사에서 놓쳤다
11. **판정표는 키가 안 맞으면 조용히 아무 일도 안 한다.** 정규식과 실패 방향이
   반대다 — 넣은 뒤 **재분류 건수를 반드시 확인하라**
12. **결함을 고쳤으면 같은 구조가 다른 적용 단위에 남았는지 보라.** #4 는 캡션
   어휘를 넓혔고 #5 는 같은 어휘의 **적용 단위**(줄 대 구간)가 틀린 것이었다

# 이 검사들이 여전히 못 보는 것

- **캡션 없는 도해.** 예시 판정의 근거는 언제나 실재하는 캡션 한 줄이다.
  줄 전체가 `예)` 인 선언은 #5 에서 근거로 받았지만, 아무 표지도 없는 도해는 못 본다
- **캡션 본문이 변환에서 소실된 도해 679건.** 예시인지 규범 도해인지 판정 불가라 규범으로 남겼다

  **재변환으로 표가 복원되면 이 유형이 새로 유입된다**
- **값의 규범적 정합성.** 값 1,217건이 그 지구의 규범으로서 조례·상위법과 맞는지는

- **하위 축의 소비 방식.** 검증기는 하위 축 코드를 보지 않는다. 소비 계약은 그쪽이

## 지켜야 할 것

1. **`article` 이 null 이면 `article_reason` 이 필수다.** 없는 조문을 가장 가까운
   h4 로 채우지 않는다. 첫 h4 앞 본문을 `unassigned_document_preamble` 로 격리하는
   `legal-statute/GUIDE.md`의 범위 생성 규율과 같다.
2. **필터를 넣기 전에 걸러낼 대상을 전수로 눈으로 확인한다.** 법령 별표
   (`건축법 시행령 [별표1]`)를 이 지침의 표에서 빼는 `LAW_CONTEXT` 필터는 제외
   437건·유지 201건을 전수 확인하고 확정했다. 규칙을 넓힐 때마다 **새로 걸리는
   항목을 다시 전수로 본다** — 넓힌 규칙이 정당한 표까지 먹는지는 양방향으로 본다.
3. **커버리지 93 과 조례 대조 커버리지 45 를 한 분모로 섞지 않는다.** 93 은 md 에서
   회수 가능한 관측 상한이고 45 는 조례 쪽 관할 교집합이다. 섞으면 검증 커버리지가
   두 배 넘게 부풀려진다. 이 문장은 산출물 `meta.coverage_note` 에도 박아둔다.
4. **`article_integrity_class` 는 codex 산출물을 실제로 읽은 경우에만 채운다.**
   못 읽으면 `null` 이고 `article_integrity_basis` 에 사유를 남긴다. 추정 금지.
   **지배값은 건수 max 가 아니라 결함 우선순위로 정한다** — `complete_count` 가
   거의 항상 최대라 max 로 뽑으면 104문서가 `완전` 이 되어 결함이 가려진다.
   `조문없음`(원본·md 양쪽 조문 0개, 48건)은 `완전`(21건)과 구분하고, `미검증`
   30건은 **결함 없음이 아니다.**
5. **`frontmatter_표` 는 소실 표 수의 하한이다.** 원본에서 센 값이라 확정값이
   아니다 — `표: 0` 으로 선언된 문서에도 셀이 줄로 풀린 표 흔적이 실재한다
   (죽산지구 도시개발구역).
6. **산출물을 쓰는 스크립트에 `if __name__ == '__main__'` 가드를 건다.** import
   만으로 산출물이 덮어써진 사고가 이 저장소에 있다.
7. **관계 필드는 원문 어휘가 그 값의 지표를 직접 수식할 때만 발급한다.** 같은 줄에
   어휘가 있다는 것만으로는 부족하다 — 어휘 후보 36 중 31 이 오탐이었고 대부분
   비율 피연산자다. 문맥상 기본값 같다는 이유로 붙이지 않는다. 발급을 넓히고 싶으면
   **정규식을 넓히지 말고 판정표에 건별로 원문 대조 결과와 함께 추가한다.**
