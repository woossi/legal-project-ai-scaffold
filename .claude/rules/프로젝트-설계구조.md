# 1. 저장소 구조

| 용어 | 뜻 |
|---|---|
| **팀** | legal(수집·변환·추출) · kb(스키마·온톨로지) · viz(도표·그래프) |
| **스킬** | 재사용 가능한 규칙·절차·실측치를 담는 단위. `.claude/skills/<팀>/<스킬명>/` |
| **에이전트 메모리** | 에이전트별 `MEMORY.md` 단일 파일. 재사용 가능한 것은 메모리가 아니라 스킬에 적재한다 |
| **rules** | 용어를 명시적으로 정의해야 할 때 쓰는 자리. 절차나 실행 코드는 두지 않는다 |
| **산출물 경로** | `output/<팀>/` 아래. 경로 규약은 각 `SKILL.md` 의 `output path` 절이 정본 |

스킬 폴더 규약 — `SKILL.md`(필수·규칙과 절차) · `scripts/*.py`(실행체) · `contract/*.json`(산출물 계약) · `references/common-mistakes.md`(규칙을 없앴을 때 유입된 것) · `case/*`(실제 사례).

# 2. 계약

| 용어 | 뜻 |
|---|---|
| **계약**(`contract/`) | 산출물이 지켜야 할 것의 정본. **스킬 문서보다 계약이 우선한다** |
| **구조 계약** | JSON Schema. 필드 존재와 타입 |
| **선언적 계약** | 그 밖의 규약 — 선행조건 · 멱등성 · 값 도메인 · 교차 제약 · 판정 파라미터 |
| **값 도메인** | 필드가 가질 수 있는 값의 집합. 실측 관측값으로 고정한다 — **새 값이 나오면 판정 로직이 바뀐 것이므로 계약을 먼저 갱신한다** |
| **교차 제약** | 파일 간에 걸리는 조건. 한 파일만 봐서는 검사할 수 없다 |
| **선행조건** | 이 산출물을 만들기 전에 있어야 하는 것. 실행 순서는 여기서 나온다 |
| **멱등성** | 같은 입력에 같은 산출물. 군집·병합은 정렬로 순서를 고정해 보장한다 |
| **불변식** | 임포트 후에도 깨지면 안 되는 조건(고아 노드 없음, dangling 없음 등). pytest 로 검사한다 |

산출물 구조를 바꿀 때는 `contract/` 를 함께 고친다. **계약 검증 통과가 완료 조건이다.**

# 3. 산출물 규율

| 용어 | 뜻 |
|---|---|
| **정본** | 그 값을 결정하는 단 하나의 자리. 두 곳이 같은 값을 정하면 반드시 어긋난다 |
| **원문 / 파생값** | 원본 문자열과 미검증 파생값은 필드를 나눈다. 섞으면 원문 복원이 불가능해진다 |
| **생성 근거** | 파생값에 남기는 산출 이유. 없는 파생값은 검증된 값과 구분할 수 없다 |
| **격리** | 판정할 수 없는 항목을 산출물에서 빼 사유와 함께 남기는 것. `reports/` · `_*.json` |
| **리포트 파일**(`_*.json`) | 그래프·산출물에 들어가지 못한 것과 사유. 결손이 아니라 기록이다 |
| **저신뢰 플래그** | 품질·확신·검증 상태를 표시해 질의에서 걸러내게 하는 필드. 확정분과 섞어 집계하지 않는다 |
| **모수** | 비율·등급의 분모. 분모를 잘못 잡으면 개별 수치가 모두 맞아도 분포가 틀린다. 등급은 조정 모수로 판정한다 |
| **재계산 필드** | 다른 파일의 동명 필드를 다시 센 값. 이름이 같아도 나란히 비교하지 않는다 |

# 4. 그래프 층 분리

| 용어 | 뜻 |
|---|---|
| **det** | 근거 사슬이 이어지는 진술. **OWL 추론 대상** |
| **prob** | 판정·분류·빈도. 추론 금지 — 넣으면 오판정이 사실로 굳는다 |
| **술어 배치** | 각 술어가 det·prob 중 어디에만 올 수 있는지. 정본은 `kb-ontology/contract/ontology.json` |
| **IRI** | 인스턴스 식별자. 패턴 정본(계약) · 발급 구현(`mint_iri.py`) · 선언(`keys.ttl`) **셋이 일치해야 한다** |
| **origin** | 간선이 어디서 나왔는지. 출처가 다르면 근거 요건도 다르므로 한 관계에 섞지 않는다 |
| **근거 요건** | 간선을 추가할 최소 조건. 요건을 못 채우면 간선을 만들지 않고 리포트에 남긴다 |
| **관측값 / 확정값** | 품질·신선도를 재는 값과 판정을 확정하는 값. **관측값을 확정값으로 승격하지 않는다** |
| **게이트** | 번호가 붙은 검증 단계(1~14). 이름과 판정은 `validate_ontology.py`·`verify_chain.py` 가 정본 |
| **미검사(skipped)** | 입력이 없어 돌지 못한 게이트. **실패가 아니다** |

# 5. 검증 규율

| 용어 | 뜻 |
|---|---|
| **품질 검증 / 계약 검증** | 대상이 다른 두 검증. 앞은 변환 품질, 뒤는 산출물 구조. **둘 다 통과해야 완료다** |
| **자기 일관성** | 같은 스크립트가 만든 두 파일이 서로 맞는 것. **검증이 아니다** — 산술이 완벽해도 판정 규칙의 구멍은 잡히지 않는다 |
| **반박검증** | 원자료 대조로 반증을 시도하는 검수. 부정 주장 → 환각 전수 검사 → 파생 필드 자기모순 → 모수 왜곡 → 파일 간 정합성 순으로 표적을 고른다 |
| **사각지대 명시** | 검사 결과를 보고할 때 그 검사가 보지 못하는 범위를 함께 적는 것 |
| **게이트 예외** | 지표 하나를 면제하고 통과시키는 것. 면제 지표·사유·나머지 지표의 통과 수치를 기록한다 |
| **육안 검수** | 자동 검증이 불가능한 항목에 남기는 표본 확인. 검사 통과를 안전 보증으로 보고하지 않는다 |
